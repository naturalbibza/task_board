# Project instructions

Коллаборативная доска задач (Trello-like): drag-n-drop, реал-тайм через Socket.IO,
шаринг по invite-ссылкам. TypeScript, pnpm workspaces, React+Vite, Express+Socket.IO,
PostgreSQL+Drizzle.

## Spec-Driven Development — обязательно

1. Перед любой задачей прочитай задачи текущей фазы. Сейчас это `specs/002-web-v2/tasks.md`
   (v2); требования — `specs/002-web-v2/spec.md`, решения — `specs/002-web-v2/plan.md`.
   `specs/001-task-board/` — спецификация v1 (историческая, менять её только при
   необходимости зафиксировать регресс). Работай строго в рамках текущей фазы.
2. Требования и архитектура живут в спеке и плане текущей версии (сейчас `specs/002-web-v2/`).
   Если задача противоречит им — сначала обнови спеку/план (и скажи об этом), потом код.
3. Новые требования от пользователя не реализуй молча: отрази их в spec.md
   (или явно пометь как out-of-scope, см. раздел «Вне объёма v1»).
4. В конце фазы отметь выполненные задачи в `tasks.md` и добавь чекпоинт-коммит
   (`docs: phase N done`).

## Команды

```bash
pnpm install            # установка
pnpm dev                # сервер + клиент в dev-режиме
pnpm typecheck          # tsc --noEmit во всех пакетах
pnpm lint               # eslint
pnpm build              # сборка client и server
pnpm deploy:vps         # ручной деплой на прод (запасной; автоматом деплоит CI/CD)
pnpm --filter @task-board/server db:generate   # новая миграция из schema.ts
pnpm --filter @task-board/server db:migrate    # применить миграции
```

Принципы разработки: см. `specs/constitution.md` (strict TS, server-authoritative,
валидация всего входа через zod в пакете `shared`, Conventional Commits).

## Ключевые правила

- **Не коммитить и не пушить самостоятельно.** git commit / git push — только по явной
  просьбе пользователя; по умолчанию изменения просто оставляются в рабочей копии.
  ⚠️ Пуш в `main` автоматически деплоит на прод (https://bibza.ru) через CI/CD —
  поэтому пушить только закрытые фазы и по явной просьбе.
  ❗ Разрешением НЕ считаются: «начинай фазу N», «проверим», «давай», просьбы править
  код или пункты задач в tasks.md (в т.ч. «пуш → CD задеплоит» в чекпоинтах фаз).
  Разрешение — только прямое: «сделай коммит», «запушь» и т.п. Если шаг фазы требует
  пуша — остановись и спроси.

- **Гранулярность коммитов:** одна незапушенная фаза — **один** коммит. Правки,
  найденные при её проверке, вносятся в тот же коммит (amend/squash), а не отдельными
  `fix:`. Отдельный коммит допустим только для исправлений уже запушенного
  (завершённого) функционала.

- Контракты (типы и zod-схемы WS-событий, REST DTO) — только в `packages/shared`;
  в `client`/`server` их не дублировать.
- Изменяя WS-протокол или модель данных: сначала `packages/shared` /
  `packages/server/src/db/schema.ts`, потом обработчики и UI.
- Схему БД менять только в Drizzle (`src/db/schema.ts`) с последующим
  `drizzle-kit generate`; сгенерированные SQL-миграции не редактировать вручную.
  Применение миграций: `pnpm --filter @task-board/server db:migrate`.
- Секреты (`JWT_SECRET`, `DATABASE_URL`) — только в `.env`; `.env` не коммитить.
- Локальные и продовые служебные данные (тестовые аккаунты, порты, адрес VPS по
  SSH, домен, содержимое серверного `.env`) — в `DEV_NOTES.md`; файл в .gitignore,
  в репозиторий и в ответы не публиковать.
- Сгенерированное (`client/dist`, `node_modules`, миграции-артефакты) не редактировать.
- Перед завершением задачи: `pnpm typecheck && pnpm lint` без ошибок.
